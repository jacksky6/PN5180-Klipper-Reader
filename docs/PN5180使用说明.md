# PN5180 Klipper 插件使用说明

本文档说明 PN5180 Klipper 插件的接线、配置和基本使用方式。第一版目标是通过 PN5180 读取耗材 NFC 标签中的信息，并可选把标签里的 `spool_id` 发送给 HappyHare。

## 功能范围

- 支持 PN5180 通过 SPI 通信。
- 支持读取 ISO14443A / NTAG 和 ISO15693 / ICODE SLIX2 标签。
- 支持从 JSON 或普通文本中提取 `spool_id`、`spool`、`filament` 字段。
- 可配置读取到 spool ID 后自动执行 `MMU_GATE_MAP NEXT_SPOOLID=<ID>`。
- 暂不包含写卡、Bambu Mifare Classic 鉴权和厂商私有二进制格式解析。

## 支持的标签

当前支持两类常见耗材标签：

- ISO14443A / NTAG213 / NTAG215 / NTAG216
- ISO15693 / ICODE SLIX2 等公开可读块标签

默认 `tag_protocol: auto` 会自动尝试 NTAG 和 ISO15693。加密卡、需要认证的卡、厂商私有格式卡即使能被 PN5180 感应，也不一定能直接读取出耗材数据。

标签内容可以是 JSON：

```json
{"spool_id": "12345"}
```

也可以是普通文本：

```text
spool_id=12345
```

插件会优先按 JSON 解析，失败后再使用文本正则提取。

## 接线

以 SLB MMU 主板的 SPI 接口为例：

| PN5180 引脚 | SLB MMU 主板引脚 |
| --- | --- |
| SCK | PB13 |
| MISO | PB14 |
| MOSI | PB15 |
| NSS | PA8 |
| RST | PC7 |
| 5V | 5V |
| 3.3V | 3.3V |
| GND | G |

`RST` 必须接到 MCU GPIO，并在配置中填写 `reset_pin`。PN5180 长时间运行后可能进入无法通过 SPI 命令恢复的状态，RST 只接 3.3V 时只能断电重上电。

本项目测试的 PN5180 模块需要同时接 `5V` 和 `3.3V`：`5V` 供给模块射频/功放部分，`3.3V` 供给逻辑电源和 SPI 电平参考。只接其中一路可能导致 PN5180 不启动或 SPI 读回全 `FF`。

IRQ、GPIO、AUX、REQ、BUSY 暂时都不接。

## 安装

将插件文件放入 Klipper：

```text
klippy/extras/pn5180.py
```

重启 Klipper 后，在 `printer.cfg` 或 MMU 相关配置中加入下面配置。

## 配置

SLB MMU 主板硬件 SPI 示例：

```ini
[pn5180 mmu_reader]
spi_mcu: mmu
spi_bus: spi2_PB14_PB15_PB13
cs_pin: mmu:PA8
reset_pin: mmu:PC7

spi_speed: 100000
scan_period: 3.0

tag_protocol: auto  # 自动识别 NTAG 和 ISO15693 标签
iso15693_blocks_per_read: 8

happyhare_enable: True
debug_log: True

command_delay: 0.005
rf_timeout: 0.05
rf_poll_interval: 0.001
rf_on_delay: 0.05
page_read_retries: 2
```

`spi_bus: spi2_PB14_PB15_PB13` 对应：

```text
MISO = PB14
MOSI = PB15
SCK  = PB13
NSS  = PA8，由 cs_pin 控制
```

如果固件中没有可用的硬件 SPI 总线名，可以临时使用软件 SPI 排查：

```ini
[pn5180 mmu_reader]
spi_mcu: mmu
spi_software_sclk_pin: mmu:PB13
spi_software_miso_pin: mmu:PB14
spi_software_mosi_pin: mmu:PB15
cs_pin: mmu:PA8
reset_pin: mmu:PC7

spi_speed: 100000
tag_protocol: auto
iso15693_blocks_per_read: 8
```

如果已经确认全部标签都是 ICODE SLIX2，可以把 `tag_protocol` 改成 `iso15693`，这样每次扫描少走一次 NTAG 寻卡流程。如果标签类型不确定，保持 `auto`。

如果当前 Klipper 环境没有 HappyHare 或没有 `MMU_GATE_MAP` 命令，把 `happyhare_enable` 设为 `False`，插件只显示和记录 spool ID，不派发命令。

### 配置项说明

必填项：

| 配置项 | 说明 |
| --- | --- |
| `spi_mcu` | PN5180 接在哪个 MCU 上；接主板就按实际 MCU 名称填写，接 MMU 板通常为 `mmu`。 |
| `spi_bus` | Klipper MCU 固件提供的硬件 SPI 总线名。SLB MMU 示例为 `spi2_PB14_PB15_PB13`。 |
| `cs_pin` | PN5180 的 NSS/CS 引脚。 |
| `reset_pin` | PN5180 的 RST 引脚，必须接 MCU GPIO。 |

常用项：

| 配置项 | 说明 |
| --- | --- |
| `spi_speed` | SPI 速度。建议先用 `100000` 跑通。 |
| `scan_period` | `READ=1` 后台读取的周期，单位秒。 |
| `tag_protocol` | 标签协议：`auto` / `ntag` / `iso15693`。不确定标签类型时保持 `auto`。 |
| `iso15693_blocks_per_read` | ISO15693 每条读命令读取的 block 数。默认 `8`，兼容性不好时可改为 `1`。 |
| `happyhare_enable` | 是否读取到 spool ID 后执行 `MMU_GATE_MAP NEXT_SPOOLID=<ID>`。 |
| `debug_log` | 是否输出每次扫描的调试日志。调试阶段建议 `True`，稳定后可设为 `False`。 |

时序项：

| 配置项 | 说明 |
| --- | --- |
| `command_delay` | 每条 PN5180 host command 后的固定等待时间。 |
| `rf_timeout` | 等待标签 RF 响应的超时时间。能读 UID 但读数据不稳定时可适当增大。 |
| `rf_poll_interval` | 轮询 PN5180 IRQ/RX 状态的间隔。 |
| `rf_on_delay` | 打开 RF 场后的稳定等待时间。 |
| `page_read_retries` | NTAG page 读取失败时的页级重试次数。 |

## G-code 命令

单次扫描：

```gcode
PN5180 NAME=mmu_reader SCAN=1
```

`SCAN=1` 不会每次都预先 RST，适合手动旋转线轴后连续多次读取。如果 PN5180 尚未初始化，插件会先初始化；如果读卡过程中判断到通信或读数据异常，会自动 RST 后重试，最多 3 次。

启动后台读取：

```gcode
PN5180 NAME=mmu_reader READ=1
```

执行 `READ=1` 时，插件会先通过 RST 硬复位并重新初始化 PN5180，然后按 `scan_period` 周期读取。实际使用中更推荐在换料/装料前启动读取，读到标签后停止，不必长期后台轮询。

停止后台读取：

```gcode
PN5180 NAME=mmu_reader READ=0
```

重新初始化：

```gcode
PN5180 NAME=mmu_reader INIT=1
```

手动硬复位 PN5180：

```gcode
PN5180 NAME=mmu_reader RECOVER=1
```

读取底层诊断寄存器：

```gcode
PN5180 NAME=mmu_reader DIAG=1
```

## 调试建议

1. 先执行 `PN5180 NAME=mmu_reader DIAG=1`，确认寄存器不是全 `0xFFFFFFFF` 或全 `0x00000000`。
2. 再执行 `PN5180 NAME=mmu_reader INIT=1`，确认能读到 firmware。
3. 然后执行 `PN5180 NAME=mmu_reader SCAN=1`，把标签靠近 PN5180。
4. 如果隔夜或长时间放置后不读卡，先执行 `PN5180 NAME=mmu_reader RECOVER=1` 或 `INIT=1`，再连续执行 `SCAN=1` 调整线轴位置。
5. 如果诊断结果大量出现 `0xFFFFFFFF` 或 firmware raw 为 `FF FF`，说明 PN5180 没有返回有效 SPI 数据。优先检查 MISO、CS、SPI bus 名称、供电、GND 和 RST。
6. 如果能读 UID 但读数据失败，先把标签保持稳定不要移动，再增加 `rf_timeout` 到 `0.1`。
7. 如果初始化偶发失败，优先确认 RST GPIO、电源和 GND。RST 必须能被 MCU 拉低再拉高。

## 推荐使用方式

建议在换料或装料前启动读取，读取到标签后停止或等待标签移除。插件会记住上一张已经处理的 UID，同一张标签未移除时不会重复派发 spool ID。

如果需要连续微调线轴位置，先执行一次 `RECOVER=1` 或 `INIT=1`，然后多次执行 `SCAN=1`。`SCAN=1` 本身不会每次都复位 PN5180，只有读卡异常时才会自动复位并重试。
